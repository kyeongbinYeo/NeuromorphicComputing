# 논문 Source data 기반 스켈레톤 코드 수정 안내

**실제 엑셀 수치를 확인했어. 우선 `configs/demo.json`의 FeTFT 값을 교체하고, MPBTFT는 감쇠 검증과 펄스 응답 수정을 나눠 진행해야 해.** 아래는 기존 스켈레톤 기준이야.

수치 출처는 `Analog reservoir computing via ferroelectric_Source data.xlsx`의 `Fig.2`, `Fig.3` 시트야. 펄스 및 읽기 조건은 Nature Communications 논문 Fig.2f, Fig.3i–j에서 확인했어.

## 1. `configs/demo.json` → `"fetft"` 전체 교체

현재의 `[1e-6, 2e-6, …]`는 예시값이야. 아래 **실제 전도도 데이터**로 바꿔.

```json
    2.40880e-7,
    2.56120e-7,
    2.68780e-7,
    2.81620e-7,
    2.94100e-7
  ],
  "ltd_conductance_S": [
    2.94100e-7,
    2.61250e-7,
    2.33962e-7,
    2.12209e-7,
    1.93465e-7,
    1.77421e-7,
    1.64563e-7,
    1.53307e-7,

    1.20094e-7,

    1.08229e-7,
    1.03027e-7,
    9.81460e-8,
    9.38470e-8
  ]
}
```

- 출처: `Fig.2!I3:J34`.
- LTP는 원본 펄스 번호 **1~16**.
- LTD는 최대값인 원본 **16번 상태부터 시작해서 17~32번**으로 내려가도록 구성했어.
- 단위는 **S**야. 다시 μS 변환을 하지 않아도 돼.
- `read_vgs_V`는 읽기 조건 기록용이야. 기존 코드는 이 값을 계산에 사용하지 않아.

**주의할 점:** 기존 코드의 배열 인덱스 `0`은 여기서는 *첫 측정 상태*야. 논문의 “펄스를 한 번도 주지 않은 상태”라는 뜻은 아니야.

이 수정만 하면 기존 `demo.py`는 배열 길이를 자동으로 읽어서 실행해. `FeTFT` 클래스 자체를 바꿀 필요는 없어.

읽기 조건은 논문 Fig.2f의 **VGS=1.0 V, VDS=0.1 V**를 확인했어. 기존 `I=G×VDS` 계산도 이 고정 조건에서 사용할 수 있어.

수정 결과가 맞는지 확인할 기준은 다음과 같아.

| 상태 | 전도도 | `read_current_A()` 결과 |
|---|---:|---:|
| LTP 첫 상태 | 1.00387e−7 S | 1.00387e−8 A |
| LTP 최대 상태 | 2.94100e−7 S | 2.94100e−8 A |
| LTD 마지막 상태 | 9.38470e−8 S | 9.38470e−9 A |

## 2. `"protocol"`과 `demo.py` → 펄스 조건은 대부분 유지

기존 4비트 설정의 다음 값들은 논문 Fig.3i와 일치해.

| 항목 | 사용할 값 |
|---|---|
| BG 펄스 전압 | `4.0` V |
| 펄스 폭 | `100e-6` s = 100 μs |
| 시간 간격 | `0.003` s = 3 ms |
| 4비트 TG 배열 | `[5.0, 3.0, 1.5, 0.0]` V |

따라서 기존 코드의 다음 부분은 유지해.

```python
mp.pulse(4.0, tg, 100e-6)
```

5비트를 실험하려면 `"protocol"`에서 **두 배열을 함께** 바꿔.

```json
"bits": [1, 1, 1, 1, 1],
"tg_V": [5.0, 3.0, 2.0, 1.0, 0.0]
```

앞서 TG 배열을 예시값이라고 설명했는데, 그림을 직접 확인하니 **기존 4비트 배열은 논문에 제시된 값과 같았어.**

## 3. MPBTFT 감쇠 → 실제 데이터로 계산한 수치

엑셀 `Fig.3`의 **W열은 시간, Y열은 BG=4.0 V의 전류**야.

이 데이터를 이중 지수식으로 피팅한 결과는 다음과 같아. **논문에 적힌 계수를 그대로 옮긴 값이 아니라, 내가 Source data로 계산한 값**이야.

| 계수 | 피팅값 |
|---|---:|
| I0 | `6.95557e-7` A |
| A1 | `7.23652e-8` A |
| A2 | `1.25922e-6` A |
| t1 | `0.00122626` s |
| t2 | `0.01917805` s |

피팅 조건은 다음과 같아.

- 원본 시간 **0.00030~0.01509 s** 구간 사용.
- 같은 시간에 기록된 전류는 평균.
- 원본 시간 **0.00030 s를 새 시간 0으로 설정**.
- 전류 RMSE는 약 **1.97e−8 A = 0.0197 μA**.
- 느린 시간상수는 관측 구간보다 길어서 추가 데이터에 따라 달라질 수 있어.

**이 값들을 기존 `"mpbtft"`에 통째로 넣고 펄스열을 실행하면 안 돼.** 해당 감쇠 곡선 하나를 확인하는 값이기 때문이야.

감쇠만 검증하려면 `demo.py`와 별도로 다음처럼 실행해.

```python
from models.devices import MPBTFT

config = {
    "baseline_A": 6.95557e-7,
    "tau_fast_s": 0.00122626,
    "tau_slow_s": 0.01917805,

    # 아래 값은 기존 생성자에 필요한 예시값.
    # 이 검증에서는 pulse()를 호출하지 않으므로 사용되지 않음.
    "reference_width_s": 100e-6,
    "capacity_A": 4e-6,
    "fast_fraction": 0.5
}

mp = MPBTFT(config)

# 원본 시간 0.00030 s에서의 피팅 상태 설정
mp.fast = 7.23652e-8
mp.slow = 1.25922e-6

print(mp.read_current_A())

mp.advance(0.003)
print(mp.read_current_A())
```

이 코드는 **전류가 시간에 따라 감소하는 부분만** 확인해. 펄스로 전류가 증가하는 부분은 검증하지 않아.

## 4. `MPBTFT.pulse()` → 아직 숫자 하나로 교체하면 안 되는 부분

다음 항목은 현재도 예시 계수야.

```json
"increment_A": 8e-7,
"capacity_A": 4e-6,
"fast_fraction": 0.5,
"tg_suppression_per_V": 0.15
```

**감쇠 피팅만으로 이 네 값을 확정할 수는 없어.** 펄스 응답과 포화 특성을 별도로 맞춰야 해.

우선 모델 결과를 비교할 정확한 기준값은 확보했어. 입력이 `1111`일 때 엑셀에 기록된 전류는 다음과 같아.

| 펄스 번호 | TG 미사용: `Fig.3!AZ3:AZ7` | TG 사용: `Fig.3!AZ11:AZ15` |
|---:|---:|---:|
| 초기 | 1.01931 μA | 1.01954 μA |
| 1 | 1.82696 μA | 1.40391 μA |
| 2 | 2.51329 μA | 1.89614 μA |
| 3 | 3.05715 μA | 2.46029 μA |
| 4 | 3.48466 μA | 3.13725 μA |

`demo.json`의 `"bits"`를 `[1,1,1,1]`로 설정하고, **시뮬레이션의 대응 측정 시점 전류를 이 표와 비교**하면 돼. 최종값만 맞추지 말고 중간 상태도 맞춰야 해.

**지금 바로 적용할 수정은 ① FeTFT 배열 교체야.** MPBTFT는 ③으로 감쇠를 따로 검증한 뒤, ④의 펄스별 측정값까지 맞추도록 `pulse()`를 보정해야 해. 감쇠 계수만 바꾸고 “논문 기반 모델이 완성됐다”고 보면 안 돼.
